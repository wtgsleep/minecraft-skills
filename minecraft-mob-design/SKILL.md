# Minecraft 怪物设计

将主题转化为有辨识度、能实际制作的怪物方案。优先沿用用户的世界观、风格、目标玩家阶段和限制；纯创意任务不必先询问加载器和版本。缺失背景时说明合理假设，不给长问卷。

## 从一个核心特点展开

- 用一句话定义玩家体验及怪物定位：普通敌人、环境威胁、精英或 Boss。默认给一个完整方案；用户要灵感列表时先给少量差异明确的短方案，不逐个写长策划。
- 外观围绕易识别的轮廓、体型、材质与动作特征展开，适配用户的原版方块风或既有风格；明确视觉体积和碰撞体积的区别。不要只靠换颜色和堆血量制造特色。
- 栖息地、出现条件、稀有度、活动时间和对其他生物的关系应服务于核心特点。考虑自然刷新、召唤或结构生成，别让奖励要求依赖击败自己才拿得到的材料。

## 行为与战斗

按需要说明待机/巡逻、发现目标、追击、攻击、恢复、失去目标和死亡的转换条件，不要求每只普通怪都做复杂状态机。

每个主要招式写清：触发条件 → 玩家能看到/听到的前摇 → 命中范围与效果 → 冷却或恢复窗口 → 可行的反制方法。距离用方块、时间用秒、生命与伤害注明单位；区分原始伤害和减伤后结果。具体数值标为初稿，并给出假定装备与难度。

- 不把无提示秒杀、无限控制或无代价瞬移当作默认难度。用户需要高压玩法时保留意图，但说明公平性取舍与可选调整。
- Boss 阶段需说明切换条件、正在施放的招式如何处理、召唤物数量上限；普通怪不强加多阶段。多人时考虑目标切换、参与者进入/退出及奖励归属。
- 检查隔墙攻击、卡高处、挖坑、拉脱、脱战回血、区块卸载重载和挂机刷取等相关边界；不要默认允许破坏建筑或追击到玩家家中。只展开会影响本方案的项目。
- 掉落、用途和获取难度相匹配；随机掉落注明概率与次数假设，避免未说明的无限资源来源。

## 控制制作成本

区分最小可玩版本与可选增强，列出需要的模型、纹理、动画、音效和逻辑。复杂骨骼、飞行寻路或大范围破坏标明额外成本，不在未查证时承诺某版本 API 或库一定支持。

默认交付短设计卡：名字与核心特点、外观/生态、行为与招式、初始属性/奖励、实现难点及试玩检查。简单请求只展开必要部分。试玩检查应有场景和预期，如玩家躲过前摇攻击、失去目标后合理脱战、多人切阶段不重复结算；未实测不能声称平衡或功能已完成。

只有用户要求精算数值时才结合可用的 minecraft-gameplay-balance；明确要求制作模组时才结合 minecraft-mod-dev。需要概念图时使用可用的 imagegen，物品掉落贴图才适用 minecraft-item-art；概念图不是实体模型、UV 贴图或动画。工具或配套技能缺失时仍可交付文字方案，不自动安装依赖、生成图片、改代码或启动游戏。
