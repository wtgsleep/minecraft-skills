# Minecraft Mod 开发

沿用项目的游戏版本、加载器、运行端和约定；缺少影响实现的关键信息才询问。“最新版”需核验；多版本须限定目标，不承诺一个 JAR 全版本兼容。

## 默认：已有项目轻量修改

- 遵守项目指令，优先利用已有项目说明定位，仅读取相关代码、资源和必要配置；不为小改动扫描全仓或重读整套资料。
- 复用已验证的 JDK、依赖、缓存及构建命令，不默认升级、清缓存或重新搭环境。新增或不确定的 API 查目标版本官方资料或实际依赖源码，不猜签名。
- 日志先看失败任务和因果异常链，需要时再扩展；避免输出整份源码、依赖列表或成功日志。
- 只调整手持大小、显示位置时修改模型或界面代码，不重新生成贴图。
- 诊断请求只解释原因；实现请求仅修改授权范围。

## 按风险验证

- 外观、布局、文案：相关资源检查、构建和受影响测试；不默认启动测试服务器。视觉效果未经游戏查看须注明。
- 伤害、事件、权限、同步或持久化：补跑对应逻辑/游戏测试；存档测试用副本，服务端逻辑检查专用服环境。
- 先确认构建任务是否串联昂贵测试，选择能产出正式包并覆盖本次改动的任务；不以省额度为由跳过必要验证。
- 不自动接受 EULA、发布模组或操作正式世界。只报告实际执行结果，构建成功不等于运行验收。
